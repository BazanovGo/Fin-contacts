# Fin-contacts: поиск инвесторов и стратегических партнёров Bazanov Trading

Воспроизводимый конвейер, который собирает из открытых официальных источников базу потенциальных
инвесторов, финансовых и торговых партнёров в России, Казахстане и других странах СНГ, оценивает их
по модели **Bazanov Partnership Score** и формирует выгрузки и аналитический отчёт.

Конвейер только исследует источники и строит базу. Он не отправляет обращения и не делает рассылок.

## Результаты (`output/`)

| Файл | Содержимое |
|---|---|
| `bazanov_partners.db` | Нормализованная база SQLite (схема ниже) |
| `bazanov_partners.csv` | Все организации: основные подтверждённые контакты, оценки, форматы сотрудничества |
| `priority_investors.csv` | Потенциальные источники капитала (группы A/C, score ≥ 40, подтверждённая способность предоставлять капитал или работа с внешними управляющими) |
| `trading_partners.csv` | Профессиональные торговые компании, дилеры, брокеры, управляющие с признаками работы на срочном/товарном рынке |
| `institutional_investors.csv` | Банки, НПФ, суверенные и государственные фонды, холдинги |
| `external_manager_allocators.csv` | Организации с признаками инвестирования во внешних управляющих / альтернативные стратегии |
| `top_100_partners.md` | Досье на 100 наиболее перспективных организаций |
| `research_report.md` | Аналитический отчёт: покрытие, распределения, качество данных, ограничения |

В CSV пропуски обозначены строкой `NULL`. Кодировка UTF-8 с BOM, поэтому файлы корректно открываются в Excel.

## Установка

Требуется Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Если вы работаете за корпоративным прокси, конвейер использует CA-бандл из переменной `SSL_CERT_FILE`
или `REQUESTS_CA_BUNDLE`.

## Запуск

```bash
# Полный сбор: обнаружение → дедупликация → обход сайтов → перекрёстные ссылки → контроль качества → оценка → экспорт
python -m investor_research run

# Пилот: не более 30 записей на этап, в отдельную базу
python -m investor_research run --limit 30 --db /tmp/pilot.db

# Только отдельные этапы
python -m investor_research run --stages cbr,naufor,dedupe,enrich,score,export

# Пересобрать CSV и отчёты из существующей базы без обращения к сети
python -m investor_research export

# Сводка по таблицам
python -m investor_research status
```

Этапы (`--stages`):

| Этап | Что делает |
|---|---|
| `cbr` | Реестры Банка России: брокеры, дилеры, доверительные управляющие, ПИФ (→ УК), НПФ. Затем карточка каждой организации `cbr.ru/finorg/foinfo/?ogrn=` с официальными email, телефоном, сайтом, уставным капиталом и лицензиями |
| `naufor` | Реестр членов НАУФОР: карточки с адресом, телефоном, email, сайтом и ИНН. Второй независимый официальный источник для России |
| `afsa` | Публичный реестр AFSA (МФЦА, Казахстан): лицензированные фирмы, виды деятельности, руководитель (SEO) |
| `listings` | Списки членов Финансовой ассоциации Армении (finarm.am), Кыргызской фондовой биржи (kse.kg) и торговых участников Astana International Exchange (aixkz.com) |
| `seeds` | Организации, отобранные вручную по результатам веб-исследования (`investor_research/seeds/*.csv`, у каждой строки есть ссылка на источник) |
| `dedupe` | Слияние дублей по ИНН/ОГРН, домену сайта и нормализованному названию |
| `enrich` | Обход официального сайта: главная страница и до 4 страниц «Контакты»/«О компании», только в пределах того же домена, с учётом robots.txt. Извлекаются email, телефоны, описание, AUM и сигналы инвестиционной деятельности |
| `crosslinks` | Новые организации по исходящим ссылкам с уже обойдённых сайтов: домен, на который ссылаются ≥ 2 известные организации, становится кандидатом и проходит проверку сайта |
| `quality` | Повторная дедупликация, проверка синтаксиса email, понижение статуса адресов на бесплатных почтовых доменах, удаление именных адресов сотрудников, сверка каждого подтверждённого контакта с текстом страницы-источника |
| `score` | Расчёт Partnership Score, достоверности, полноты и форматов сотрудничества |
| `export` | CSV, `top_100_partners.md`, `research_report.md` |

## Остановка, возобновление и обновление

- Каждая загруженная страница сохраняется в кэше `.cache/http_cache.db`. Повторный запуск в течение
  `CACHE_TTL_DAYS` (30 дней, `investor_research/config.py`) берёт страницы из кэша, поэтому прерванный
  сбор продолжается почти мгновенно с места остановки.
- Обход сайтов отмечает обработанные компании в таблице `checkpoints`. После `Ctrl+C` достаточно
  запустить ту же команду ещё раз.
- **Инкрементальное обновление:** `python -m investor_research run` повторно читает реестры (новые
  лицензиаты добавляются, существующие записи обновляются по ИНН/ОГРН) и обходит только сайты новых
  компаний. Чтобы перепроверить все сайты, добавьте `--refresh`. Чтобы получить свежие данные раньше
  истечения TTL кэша, удалите `.cache/http_cache.db`.
- Каждый запуск записывается в `collection_runs`, ошибки — в `run_errors`, покрытие источников — в
  `source_coverage`. Журнал работы пишется в `.cache/collector.log`.
- `--offline` использует только кэш (например, чтобы пересчитать данные без сети).

## Как расширить охват

- **Новые организации вручную:** добавьте строки в `investor_research/seeds/*.csv`. Колонки:
  `legal_name, brand_name, country, city, website, category, priority_group, discovery_channel,
  discovery_url, note`. Колонка `discovery_url` обязательна: это публичная страница, где найдена организация.
  Контакты для таких организаций берутся только с их официального сайта на этапе `enrich`.
- **Новый реестр:** напишите модуль в `investor_research/connectors/` с функцией
  `ingest(db, fetcher, limit)` и зарегистрируйте его в `DISCOVERY` в `__main__.py`.
- **Словари сигналов** (хедж-фонды, внешние управляющие, фьючерсы и т. п.) находятся в
  `config.SIGNALS`.

## Схема базы данных

- `companies` — организация: название, страна, город, сайт и его статус, категория, группа A–D,
  описание, AUM, капитал, инвестиционный фокус, инструменты, флаги `has_trading_desk` и
  `allocates_external`, руководитель, регуляторный статус, `partnership_score`, `confidence_score`,
  `completeness_score`, `score_breakdown` (JSON с объяснением каждого балла), `relevance_reason`, класс,
  `last_verified_at`.
- `company_identifiers` — ИНН, ОГРН, домен, номер лицензии AFSA, карточка НАУФОР. По ним обеспечивается
  уникальность организации.
- `contacts` — email, телефон, сайт, страница контактов, профиль LinkedIn. У каждого контакта есть
  `source_url`, `source_kind` (regulator / sro / exchange / association / company_site),
  `verification_status` (confirmed / unverified / invalid) и примечание.
- `sources` — происхождение фактов: URL, тип источника, дата обращения, HTTP-статус,
  `extracted_evidence` (поля реестра или фрагменты текста с найденными сигналами).
- `licenses` — лицензии и разрешения: регулятор, вид, номер, статус, источник.
- `partnership_opportunities` — возможные форматы сотрудничества: обоснование, подтверждающие данные,
  ограничения, приоритет, `basis` (fact / analytical_assumption).
- `collection_runs`, `run_errors`, `source_coverage`, `checkpoints`, `discovery_candidates` — служебные
  таблицы для журналирования, возобновления и обнаружения новых организаций.

## Модель Bazanov Partnership Score (0–100)

| Критерий | Максимум | Основные признаки |
|---|---|---|
| Соответствие профилю | 25 | Категория (A > B > C > D), хедж-ПИФ / ПИФ товарного рынка по реестру ЦБ, упоминание на сайте хедж-фондов, family office, prop trading, альтернативных инвестиций |
| Способность предоставлять капитал | 20 | Лицензии УК/ДУ/НПФ/банка/дилера, число действующих ПИФ, уставный капитал, опубликованный AUM |
| Финансирование трейдеров и внешних управляющих | 20 | Упоминание внешних управляющих, фондов фондов, посевного капитала, финансирования трейдеров; фонд фондов в реестре |
| Товарные рынки, деривативы, квант | 15 | Фьючерсы, срочный рынок, нефть/газ/металлы, алгоритмические стратегии, лицензия AFSA на фьючерсы |
| Стратегическое партнёрство | 10 | Возможность запустить фонд, инфраструктура фондов, холдинг, венчур/PE, финтех |
| Прямые корпоративные контакты | 10 | Подтверждённые email (5), телефон (3), доступный сайт (2) |

Классы: 80–100 — приоритетные партнёры, 60–79 — перспективные, 40–59 — дополнительные кандидаты,
0–39 — низкая релевантность. Баллы начисляются только за найденные признаки, отсутствие данных оценку
не снижает. Пункты, выведенные из категории, а не из опубликованного факта, помечены как
«[предположение]» и уменьшают `confidence_score`.

## Правила работы с данными

- Сохраняются только корпоративные контакты, опубликованные открыто. Именные адреса сотрудников (вида
  `n.surname@`) не хранятся даже при публикации (`normalize.looks_personal_email`). Адреса по шаблонам не
  угадываются. Мобильные номера и адреса на бесплатных почтовых доменах из списков членов бирж не
  сохраняются.
- Контакт получает статус `confirmed`, только если он опубликован регулятором, СРО, биржей или
  ассоциацией, либо найден на официальном сайте и его домен совпадает с доменом сайта.
- Запросы идут не чаще одного раза в 1,5 секунды на хост. robots.txt соблюдается, страницы с
  авторизацией и CAPTCHA не обходятся. Сайты, блокирующие доступ (KASE), не обходятся.
- Поисковые системы автоматически не опрашиваются: их условия использования это запрещают.

## Структура репозитория

```
investor_research/
  __main__.py      CLI и оркестрация этапов
  config.py        Пути, вежливость краулера, словари сигналов
  db.py            Схема SQLite и функции доступа
  fetch.py         HTTP: robots.txt, rate limit, повторы, кэш
  normalize.py     Нормализация названий, доменов, email, телефонов
  enrich.py        Обход сайтов и извлечение контактов и сигналов
  quality.py       Дедупликация, валидация, обнаружение по ссылкам
  scoring.py       Partnership Score, форматы сотрудничества
  export.py        CSV, отчёт, топ-100
  connectors/      cbr, naufor, afsa, listings (finarm, kse, aix), seeds
  seeds/           Отобранные вручную организации со ссылками на источники
output/            Результаты
```
